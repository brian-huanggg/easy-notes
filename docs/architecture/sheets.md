# Sheets (`.csv`, `.tsv`)

- **Does**: RevoGrid editing (edit cells, add / delete rows and columns, sorted and filtered views); display settings such as column width and frozen columns are stored in `.csv.meta.json`; `![[x.csv]]` embeds a table preview in md.
- **Does not**: formulas, multiple sheets, charts. CSV stores only data; when spreadsheet features are needed, "open with another app" hands the file to Numbers / OnlyOffice.
- **Implementation**: the Swift side does RFC 4180 parsing and serialization and the WebView receives only row data. Unmodified rows are written back byte for byte (quote style and line endings unchanged), keeping diffs and merges clean.

**Design decisions**:

- **Plugin**: `Packages/KindSheet`, depending only on EasyNotesCore / EasyNotesUI. Both `.csv` and `.tsv` are supported with one parser that differs only in the delimiter (`,` / tab).
- **Grid component: RevoGrid (built-in editor)**: verified on real Mac and iPad hardware: typing Zhuyin directly after selecting a cell loses no characters, Enter during composition (`isComposing`) does not end editing, 10,000 rows scroll at 60 fps, the bundle is about 334 KB, and the WebContent process ends after closing. So RevoGrid's built-in editor is used with no separate input layer. Fallback: if characters are lost in some situation, place a permanently focused hidden `textarea` at the selected cell (as Google Sheets does; the key points are deferring `focus()` to the next frame and locating with `.rgCell[data-rgrow][data-rgcol]`), still judging Enter during composition by `isComposing`. Only after that fails would a self-written TS virtual grid or a native grid be used; the model is unaffected.
- **Model (`SheetDocument`)**: each record has a stable row id (assigned in order when the file opens, later rows continue the numbering, never written to the file), its fields and its original bytes; the line ending (`\n` / `\r\n` / empty when the file ends without a newline) is stored separately and is not part of the record. The edit API matches the Bridge ops: `setCell`, `insertRows`, `deleteRows`, `insertColumn`, `deleteColumn`; a new row is padded to the current column count, and adding a column does not touch blank lines.
- **Model: keep original bytes**: each record keeps its original bytes and its parsed fields; an unmodified record is written back as is, and a modified one is regenerated in the file's style. Detected: line ending (LF / CRLF, majority wins), quote style (always / only when needed), BOM, whether the file ends with a newline. Rows with a different column count are kept as is, padded with blanks for display, and the padding is not written back unless edited.
- **Encoding**: UTF-8 (with or without BOM) is editable; a file detected as Big5 (common in Taiwanese Excel exports, decoded as CP950) opens read-only with "Convert to UTF-8" offered; anything else is shown as lossy UTF-8, read-only. Delimiters, quotes and line endings are all ASCII and Big5's second byte never falls on those values, so parsing is always done on bytes and then each field is decoded. A read-only file skips `renameLinks`, and merge accepts only identical sides.
- **Index**: title = file name; `plainText` = cell contents (capped so huge files do not slow FTS); summary "CSV · 86 rows · 5 columns"; `[[links]]` in cells go into `links` and `renameLinks` updates them too.
- **Merge**: diff3 per **record** (a quoted field may span lines, so physical lines are not the unit), using Core's generic `Diff3.merge` and handing conflict hunks to its `resolve`: when both sides changed different cells of the same record (or adjacent records) it merges record by record and then cell by cell; when both sides add rows at the same position (most commonly both appending at the end) both are kept, local first; the same cell changed to different values, one side deleting a row while the other edits it, or different column counts → conflict copy. Before merging, a final record without a trailing newline gets one for comparison, and the result is restored in the local style (BOM, trailing newline). Adding or deleting a column changes every row → conflict copy (accepted).
- **Editor and Bridge**: each file open creates its own `WebEditorHost` (`SheetSession`, registered by `SheetController`) and on close writes the file before releasing (not shared with Markdown's pre-warmed WebView). `sheet.load(json)` sends all rows at once (a JSON string, `JSON.parse` on the JS side; 10,000 rows take about 0.1 s in Chromium), each row carrying the stable row id Swift assigned (so sorting or filtering can still map back to the original row); JS sends `edit` (a JSON string of ops: `set`, `insertRows`, `deleteRows`, `insertColumn`, `deleteColumn`, `order`) only **when cell editing ends**, not on every keystroke, so the typing hot path never crosses the Bridge. Rows added by JS get negative ids of their own so Undo need not wait for Swift and cannot collide with Swift-assigned ids. Swift applies the ops to the model and writes the file 300 ms after editing stops; if applying fails (the model and the view disagree) the model wins and a fresh `load` is sent. It registers an `EditorController`: `externalChange` first three-way merges unwritten edits with the external content (external wins if they cannot merge), `replaceContent` lets unchanged rows keep their ids, then `applyRemote` updates the view while preserving the selection; while a cell editor is open it is deferred until editing ends (otherwise closing the editor would write the stale value back). `flush` ends the cell being edited and saves immediately. Undo is implemented by JS as an op stack (an undo is also an ordinary `edit`); ⌘Z / ⌘⇧Z are handled in JS and handed to the input box while a cell is being edited. The clipboard uses RevoGrid's built-in TSV, interoperable with Numbers / Excel. `addMenu("Table")` provides insert / delete row and column, sort by this column and write, freeze first column, first row is header (the same commands are in the toolbar).
- **Header row**: by default the file's first row is pinned on top (RevoGrid's `pinnedTopSource`), bold, and excluded from sort and filter (including "sort by this column and write"); column names are A, B, C…. With "first row is header" (display setting `headerRow`) off, the first row is an ordinary data row. Limitation: a pinned row does not support "type right after selecting"; Enter or a double click is needed to start editing.
- **Toolbar, formula bar and status bar**: the toolbar and formula bar sit above the grid and the status bar below, all built inside the grid's WebView (HTML, icons as `symbol:///` SF Symbols used as CSS masks) rather than native SwiftUI: selection state is already in JS and buttons must be enabled by selection, so a native bar would need a Bridge sync on every selection change; the formula bar is text input, and a native one would put the typing hot path across the Bridge. Mac and iPad share one implementation (iPad has no menu bar, so the "Table" menu commands are available through the toolbar).
  - **Toolbar**: undo / redo | insert row above / below, delete row | insert column left / right, delete column | sort ascending / descending by this column and write | freeze first column, first row is header (toggles, accent color when on). Buttons call the same commands as `exec` directly without Swift, and do not steal the grid's focus (`preventDefault` on `mousedown`). All are disabled when read-only; undo / redo are disabled when there is nothing to undo / redo.
  - **Formula bar (name box + fx)**: the name box shows the current cell as column name + row number, the same as the row header (the header row is row 1; after sorting or filtering the position on screen). fx is a multi-line input showing the cell's full content (including line breaks), suited to editing long text; it expands to at most 6 lines on focus. Enter writes and returns to the grid, ⇧Enter / ⌥Enter inserts a newline, Esc discards and returns to the grid, blur writes; Enter during composition (`isComposing`) does not write. Writing goes through the ordinary `set` op and the Undo stack, the same as editing in the cell, and nothing is sent if the content did not change. Typing changes only the input and sends no message. While the input is unfocused it follows selection, the end of cell editing and external changes; while focused it is not overwritten by external changes (on write the row is found again by row id, and the write is abandoned if the row was deleted).
  - **Status bar**: on the left "N rows · M columns" (excluding the header row); with two or more cells selected the right side shows a count (non-blank cells) and, when numbers are present, their sum and average. Only plain numbers are recognized (optional sign, decimal point, thousands commas), displayed with `Intl.NumberFormat` by language. Display only, never written to the file (no formulas).
- **Sorting and filtering affect only the view**: the file is not rewritten (re-sorting the whole file would change every row, which diff3 cannot merge); an explicit "sort by this column and write" is offered when needed.
- **Display settings `.csv.meta.json`** (the same for `.tsv.meta.json`, `SheetMeta`): `{version, columns: [{width}], frozenColumns, headerRow}`. `columns` follows column order, a missing `width` = default width (140), when shorter than the column count the remaining columns are default and trailing default columns are not written; missing fields use defaults (`frozenColumns` 0, `headerRow` true), so hand-edited or older sidecars still load.
  - **Who changes, who writes**: JS changes display settings (dragging column width, "freeze first column", "first row is header") and only then sends the whole thing to Swift in a `meta` message (JSON string), written with the same 300 ms delay as `edit`; Swift also sends it on `load`. The sidecar is created only when settings are not default, and once it exists it is updated as usual (written even when reset to defaults, never deleted).
  - **Adding / deleting columns**: when JS applies `insertColumn` / `deleteColumn` it moves `columns` along (an inserted column has the default width), adjusts `frozenColumns` by one when the insertion / deletion is within the frozen range, then sends `meta`; undoing a column deletion restores the default width. External tools adding or deleting columns do not adjust the sidecar (widths may land on another column, accepted).
  - **Companion**: `CSVMetaKind` / `TSVMetaKind` register with `addCompanionKind` and `companionOf` strips `.meta.json` (the companion mechanism: hidden in lists, indexed and synced as usual, renamed / moved / deleted, including permanently deleted, with the main file). When the sidecar of an open sheet is changed externally or rewritten by sync, `SheetController.externalChange` receives the sidecar path and after merging updates the view with `applyMeta`.
  - **Merge**: per-field three-way merge (`frozenColumns`, `headerRow` and each column's `width` compared separately): a field changed on one side takes that side, changed to different values on both sides local wins; with no common base the defaults are the base. No timestamps are needed; losing a display setting is cheap. If one side is not valid JSON the other is used, and only when both are invalid does it become a conflict copy.
- **Preview and embed (`SheetPreview`)**: one for CSV and one for TSV (carrying the delimiter). `makePreview` draws a PNG of the first 8 rows × 6 columns in the background with CoreGraphics + CoreText, laid out as the design's `C/Thumb CSV` (`otUrV`): header row 22 pt (`type-csv-soft` background, `type-csv` bold text), data rows 18 pt, font size 8.5, grid lines between columns and under rows, no outer border; column width follows content, limited to 44–120 pt, overflowing text truncated with "…", multi-line cells drawing only the first line; 2× pixels. The background is transparent with a light palette, and dark mode inverts at display time (as for the whiteboard: cards use `colorInvert` + `hueRotation`, md embeds use CSS `invert(93%) hue-rotate(180deg)`). The first row is always drawn as the header: the preview is cached by the main file's content hash and does not read the display-settings sidecar. On a card the table is placed top-left at its natural size (times the card scale) with overflow clipped; `lines` is the first 4 cells of the first row, and with no image (empty file) a `ThumbTable` skeleton shows. `![[x.csv]]` uses the same image through `embed://`, so the Markdown plugin does not need to know about tables.
- **New and import**: `addKind` (`tablecells`, `type-csv`), `addNewFile("New Table")` (CSV; the template is one header row "Name,Notes", no shortcut), `addImport("Import CSV…")` (`.csv` only; TSV is placed in the vault by Finder or other tools); `addVaultGuide` describes the table conventions in English (UTF-8, first row is the header, quoting rules, keep the original style and change only needed rows, do not edit `.csv.meta.json`, Big5 read-only).
