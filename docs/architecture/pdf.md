# PDF Ink and Annotation

- **Does**: open a PDF; pen (fountain, ballpoint, pencil, hold to straighten), highlighter, eraser, lasso selection, sticky notes; export a PDF with annotations merged in.
- **Does not**: insert blank pages, page thumbnails and reordering, PDF text search, handwriting recognition, creating new PDFs (import only).
- **Implementation**: `PDFView` + `PDFPageOverlayViewProvider`, with one `PKCanvasView` overlaid on each visible page and recycled when it leaves the screen, so a large file cannot exhaust memory (verified on a real device, see below). `drawingPolicy = .pencilOnly`: fingers scroll and zoom, Pencil writes.
- **Format**: the original PDF is never modified. Annotations are stored in `<file name>.pdf.ink` (JSON): `pdfHash` + Excalidraw elements grouped by page number. `.pdf.ink` is hidden in the file tree.
- **Platforms**: macOS shows the PDF and all annotations, and sticky notes can be added, moved, resized and edited; ink is view-only.

**Design decisions**:

- **Shared `ExcalidrawKit`**: the element model, `merge`, `InkStroke` / PencilKit conversion, `ElementGeometry`, `TextLayout`, `ElementPainter` and `SceneRenderer` moved from KindWhiteboard into the shared library (see "Dependency rules" in the [README](./README.md)) and both plugins depend on it. Canvas components such as the layer tree, editing core and text boxes stay in KindWhiteboard; they move individually only when PDF really needs them.
- **Sidecar format**:

  ```json
  {
    "type": "easynotes-pdf-ink",
    "version": 1,
    "pdfHash": "<SHA-256 of the PDF>",
    "pages": { "0": { "elements": [ /* Excalidraw elements */ ] } },
    "files": {}
  }
  ```

  Page numbers start at 0 and pages without annotations are not written. Coordinates are the page's **unrotated** cropBox page coordinates: unit PDF point, origin top-left, y down (the same as Excalidraw); the page's `rotation` is applied only for display and export. Elements follow Excalidraw rules (`version`, `versionNonce`, `updated`) and unknown fields are preserved.
- **Strokes**: pen = `com.apple.ink.pen` (fountain), `monoline` (ballpoint), `pencil`; highlighter = `com.apple.ink.marker` (freedraw's `opacity` preserves transparency); all convert through `ExcalidrawKit`'s `InkStroke`. The eraser (`PKEraserTool`) and lasso (`PKLassoTool`) are set by the shared ink toolbar (see "Ink toolbar" in [ui.md](./ui.md)).
- **Sticky notes**: the same standard combination as the whiteboard's sticky note (a borderless rectangle `#ffec99` + text with `containerId`), displayed directly on the page, movable and resizable, default 160×160 page points, font size 14. Editing overlays a native text box (iOS `UITextView`, Mac `NSTextView`) and never writes back during Zhuyin composition. Stacking order: page < sticky notes < ink (consistent with the whiteboard's "ink above structural elements", so you can write on a sticky note).
- **macOS sticky notes**: the bottom-right "Sticky note" button adds one at the center of the visible area of the current page and edits it directly. The overlay receives events only when the mouse is over a sticky note and leaves everything else to PDFView (text selection, scrolling). Hovering shows an outline and a resize handle at the bottom right. Drag to move, drag the handle to resize (minimum 40 page points, text re-laid out at the new size): during a drag the annotation layer redraws only this note's area to hide it, and a synchronously drawn preview view (`NSView.draw`, not the tiled `CATiledLayer`: tiles draw asynchronously, and a not-yet-drawn tile at the new position would leave a corner of the note missing and expose the PDF text underneath) follows the cursor; the write happens once on release. Double-click or context-menu "Edit" overlays an `NSTextView` (sticky-note background, font size following the scale); text is written back and re-laid out only when editing ends (click elsewhere, Esc, `flush` before switching files), so nothing is written during Zhuyin composition; context-menu "Delete". The edit box on a rotated page does not rotate (the displayed text still rotates with the page).
- **Page overlay**: overlay view = sticky-note layer (`ElementPainter`) + `PKCanvasView`. Ink tools match the whiteboard ("Ink toolbar" in [ui.md](./ui.md): pen, highlighter, eraser, lasso; selecting one enters ink mode and "Select" leaves it); in ink mode a finger scrolls and zooms and only a long press drags a sticky note; when off, both Pencil and finger can tap and drag sticky notes. iPad uses `.pencilOnly`; iPhone writes with a finger only in ink mode. The canvases of all pages use the same `InkSettings` tool (applied when a new overlay is created, updated everywhere when the tool changes), each with its own `StraightLineAssist`.
- **iOS sticky notes**: the toolbar's "Sticky note" adds one at the center of the visible area of the current page and edits it directly. One tap selects (outline, bottom-right resize handle, "Edit / Delete" menu), another tap edits; outside ink mode both Pencil and finger can tap, drag to move and drag the handle to resize, while in ink mode only a finger taps and only a long press drags (Pencil is a pen). The sticky-note gestures are installed on a container around PDFView (PDFKit does not always hand touches to the overlay) and converted to each page overlay to find the note; the overlay itself intercepts no touches (only the ink-mode canvas and an active text box receive them), and tap and drag make PDFView's scrolling and text selection wait for them to fail (zoom and the canvas do not wait). The drag preview, outline and handle are shared with macOS (`StickyPreviewView` draws synchronously and is inserted under the canvas). Editing overlays an opaque `UITextView` (above the ink, covering the whole note, so the annotation layer neither hides its text nor redraws it); text is written back when editing ends (tap elsewhere, dismiss the keyboard, external-keyboard Esc, switching ink mode, `flush`), and composing text is committed first; the text box stays 0.25 s longer so the annotation layer finishes redrawing the new text in the background and the PDF underneath is never exposed. On iOS, sticky-note operations (add, move, resize, text, delete) are also recorded in the model Undo; macOS has no model Undo.
- **Annotation layer (shared by both platforms)**: the bottom of each page overlay is a `CATiledLayer` where `SceneRenderer` (using `ElementPainter` internally) draws that page's sticky notes and strokes in tiles on a background thread: when zoomed in, tiles are redrawn at the scale, which keeps them sharp and draws only what is visible; a whole-page bitmap at 5× zoom reaches hundreds of MB and is not viable. On Mac that is the only layer; on iOS each overlay also has a `PKCanvasView` above it that displays strokes even outside ink mode (switching modes needs no redraw), so on iOS the annotation layer does not draw freedraw (`drawsFreedraw: false`). The canvas is always light (`overrideUserInterfaceStyle = .light`; PencilKit inverts stroke colors in dark mode, and the toolbar colors are the actual colors on a light canvas). When annotations change only pages that have an overlay are redrawn.
- **Open flow**: `PDFDocument(url:)` reads pages lazily; `pdfHash` is computed in the background (a large file never blocks the main thread) and, when there is no sidecar, the same background job runs `claimOrphan` and, after claiming, notifies the sync layer through `DocumentSession.fileMoved`. The sidecar is created on the first annotation write with the `pdfHash` at that time.
- **Memory**: in-memory annotations are a "page number → elements" dictionary (cheap); a `PKDrawing` exists only for pages with an overlay; on every `canvasViewDrawingDidChange` that page's strokes are converted back to elements (Undo also needs before and after states), so recycling an overlay needs no extra save and just discards the canvas. Strokes on the canvas are converted with `PKStroke.transform` (page → overlay uses `pageToView`); on write-back points go through the inverse of `pageToView` and point sizes are multiplied by the scale of both transforms, so stroke width is stored in page units and round trips unchanged.
- **Undo lives in the model, not in `PKCanvasView`**: overlays are recycled, and the undo PencilKit registers on a canvas would point to a released view. The `PKCanvasView` subclass returns a private `undoManager` (swallowing PencilKit's own registrations); on `canvasViewDrawingDidChange` the before and after strokes are compared and registered with the window's undoManager as "page number + before / after elements"; undoing changes the model and syncs to the canvas only if the page is on screen. Undo runs across pages in time order; `version` always increases (same as the whiteboard). Verified on a real device.
- **iPad Air M1 real-device findings**, implementation rules:
  - `pageOverlayViewProvider` must be set before assigning `document`; `isInMarkupMode = true`. The `PKCanvasView` inside an overlay disables its own scrolling (`isScrollEnabled = false`) so finger drags reach PDFView.
  - Page coordinates ⇄ overlay coordinates: never assume the overlay's layout; always convert with PDFKit (three points on the page, origin / top-right / bottom-left, go through `PDFView.convert(_:from: page)` and then to the overlay to derive an affine transform), recomputing when the overlay size changes. Reason: on iOS outside ink mode, the overlay of a rotated page is the **unrotated** bounds plus a rotation `transform` (the prototype applied `rotation` itself in ink mode and still aligned, presumably because the layout differs with `isInMarkupMode`), so applying `rotation` yourself would rotate twice. Pages rotated 90 / 180 / 270 align correctly.
  - The container view is the permanent first responder, and its `undoManager` is the model Undo, so system ⌘Z and the three-finger swipe find it directly.
  - PencilKit registers undo after the delegate callback: clear the canvas's private `undoManager` records on the next run-loop turn.
  - **Sharpness**: the overlay sits inside PDFView's zoom transform and PencilKit rasterizes at the screen scale by default, so zooming in blurs. 0.25 s after zooming stops, set the canvas's (and its internal subviews') `contentScaleFactor` to "screen scale × the overlay's actual scale on the window", **with no upper limit** (a cap of screen × 4 blurs at 4–5× zoom because the scale includes the fit zoom PDFView opens with).
  - Numbers: 60 FPS (the 60 Hz cap), longest frame 16.7 ms; with 200 pages, 30 strokes per page and auto-scrolling (about 6,000 pt/s), memory stays at 280–300 MB and does not grow with scrolling.
- **Saving and external changes**: the sidecar is written 500 ms after interaction stops; it registers an `EditorController`, where `externalChange` (a sidecar pulled by sync) is merged into memory by element merge and updates visible pages, and `flush` saves immediately.
- **Merge**: `.pdf` is an opaque file (different content → conflict copy). `.pdf.ink` merges per page, each page using the whiteboard's element merge (`id` + `version`); when `pdfHash` differs the local one is kept.
- **PDF replaced** (`pdfHash` mismatch): annotations still show by page number, with a banner on top "The PDF has changed; annotations may be misaligned", and `pdfHash` is updated only when "Keep annotations" is pressed.
- **Companion files (a Core extension point that knows no types)**: `DocumentKind.companionOf` (default nil); `.pdf.ink` returns "the path with `.ink` removed"; a companion's path must start with its main file's path, and on rename Core replaces only the main file's path and keeps the suffix. `PDFKind` registers with `addKind` and `PDFInkKind` with `addCompanionKind` (it enters KindRegistry but is not a filter chip). Core then:
  - Hides companions from the file tree, document list, search, `[[link]]` resolution and "Recently Deleted"; they are still indexed (hash), synced and merged as usual.
  - Handles the companion together with the main file on in-app rename, move (`VaultFS.rename`) and delete (`VaultFS.trash`), and notifies the sync layer and editors; restoring a main file from "Recently Deleted" also restores the companion recently deleted at the same path next to it.
  - When the companion of an open file is changed externally or rewritten by sync, `externalChange` carries the companion's path to the editor (the PDF editor merges the sidecar).
  - External tool renames a PDF: when the sync layer's scan infers a main-file rename (same hash), it moves the sidecar left behind next to the new name and keeps the file id. When it cannot infer (for example signed out of sync), opening a PDF with no sidecar uses `PDFInk.claimOrphan` to find an orphan sidecar whose main file does not exist and whose `pdfHash` matches (same folder first) and adopts it; after the move the caller notifies the sync layer.
- **Code structure**: `KindPDF/Model/`: `PDFInk` (sidecar read / write, per-page merge; `scene(page:)` treats a page as an `ExcalidrawScene`, so stroke conversion, rendering and sticky notes reuse `ExcalidrawKit`), `PDFPageGeometry` (unrotated page coordinates ⇄ display coordinates, `displayTransform`, PDF user space). `pdfHash` has the same format as the sync layer's content hash (lowercase hex SHA-256).
- **Index and preview**: `PDFKind.index` has only the title and a summary ("N pages"); sticky-note text is not indexed yet. List thumbnail = page 1 (without annotations, cached by PDF hash; sidecar changes do not invalidate it): drawn in the background with CoreGraphics's `CGPDFPage` as a white-background PNG (longest side 800 px, applying the page's `rotation`), not inverted in dark mode (the paper stays white); on the card it is a sheet of paper on a gray background with the type badge top-left and page count top-right, the same as the design's `C/Thumb PDF`.
- **Import**: `addImport("Import PDF…")` copies into the current folder; PDFs already in the vault (for example in `Attachments/`) also appear in the list because `.pdf` is registered.
- **Export: flatten everything**: `PDFExporter` (`KindPDF/Model/`, CoreGraphics only) draws each original page with a `CGPDFContext`: `CGPDFPage.getDrawingTransform(.cropBox, …)` applies the cropBox and `rotation`, and the output page's size is the rotated cropBox and carries no `rotation` itself. `SceneRenderer` (sticky-note layout uses the same `TextLayout`, matching the screen) then draws strokes and sticky notes as vectors with coordinates converted through `displayTransform`; highlighter transparency is kept as CG alpha, and sticky-note text is vector text that other readers can select and search. The original PDF is untouched. After export annotations can no longer be edited in other apps, in exchange for consistency in every reader and in printing.
  - **Flow**: the entry is the iOS toolbar and the Mac bottom-right "Export", which opens the export sheet. It first `flush`es, hands the annotations in sidecar format (`PDFInk` is not `Sendable`) to a background job, reads pages lazily with `CGPDFDocument`, draws page by page and releases page by page (even a textbook-sized file need not be read into memory whole); the sheet shows "page N / M" progress and can be cancelled; cancellation or failure leaves no partial output. When done the output sits in a temporary folder and the sheet offers "Share…" (`ShareLink`) and "Save to the PDF's folder"; closing the sheet deletes the temporary file.
  - **File name**: the shared name is `<name> (annotated).pdf`. Saving into the vault never overwrites: a name clash numbers automatically as `(annotated 2)`, `(annotated 3)`… (the same numbering rule as `VaultFS.importFile`). What is saved is an ordinary PDF: it appears in the list, is indexed and synced as usual, and has no sidecar.
