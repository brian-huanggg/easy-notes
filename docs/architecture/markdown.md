# Markdown

- **Features**: Live Preview, `[[link]]` + backlinks, `[[` autocomplete, link rename, tags, FTS5 search, `![[x.excalidraw]]` / `![[x.csv]]` embedded previews, card syntax highlighting, directly editable tables, math (LaTeX), property panel, find in note, Writing mode (focus, typewriter scrolling, word count).
- **Implementation**: CM6 + incremental Lezer parsing; one pre-warmed WebView where switching notes only swaps `EditorState`; the Bridge protocol is below.
- **Embeds**: `LinkTarget` carries `hash` (pushed with `setLinkTargets`, sent only when the index changes, never on the typing path); CM6's `EmbedWidget` finds the target by full path or "name.extension" and emits `<img src="embed:///…?h=<hash>">`. Image extensions still use `vault://`; `.md` is not embedded; when no target is found the raw syntax is shown. When the hash changes only `src` is swapped and the old image stays until the new one has loaded. A click opens the target; ⌘ / ⌥ click shows the raw md. Dark mode uses CSS `invert(93%) hue-rotate(180deg)`.
- **Line endings**: when every line ending in the file is `\r\n`, `EditorState` gets `lineSeparator` and write-back uses `sliceDoc()`, preserving line endings byte for byte; mixed endings are normalized to `\n` as CM6 does by default. Multi-line insertions are always converted to `Text` (`lines` in `lineBreak.ts`) and never inserted as a string containing `\n`; `applyRemote` computes the diff in doc coordinates and rebuilds the state when the line ending changes.
- **Zhuyin composition**: the document is not modified while composing (`view.composing`): saving is deferred (`flush` reschedules), content received by `applyRemote` is held, and after `compositionend` it is applied once CM6 has read the chosen characters from the DOM (about 50 ms). Changing a range that covers the cursor during composition interrupts the input method and leaves Zhuyin symbols in the document.
- **Tables** (`table.ts`, `tableWidget.ts`): top-level GFM tables in the document render as a grid (block widget, StateField) edited by clicking a cell, Notion-style; cells not being edited render inline md (bold, code, links, math, `<br>`) and switch back to raw text while editing. Tab / Shift-Tab, Enter, ↑↓ move; Tab in the last cell or Enter in the last row adds a row; Esc leaves to the line below the table; the "+" at the bottom and right adds rows and columns, and a cell's "⋯" menu inserts, moves and deletes rows and columns and sets alignment. Drag handles sit at the left of the first cell of each body row and above each header cell (shown on hover, always semi-transparent on touch devices): dragging uses Pointer Events, the insertion line moves when crossing the midline of an adjacent row or column, and on release `moveRow` / `moveColumn` rewrites the table (alignment follows the column); no drag (< 4 px) counts as a click and opens that cell's "⋯" menu. The header row is pinned to the top and cannot be dragged. Handles sit in the top and left padding of `.cm-table-scroll` (negative margin offsets it so the table still aligns with the body text; the left side uses the scroller's gutter), so horizontal scrolling does not clip them. Editing one cell replaces only that cell's text (all other bytes unchanged); only row / column operations rewrite the whole table (standard `| a | b |`, `| --- |` format). A cell is a `contenteditable="plaintext-only"` inside the widget; keyboard, mouse and composition events are never given to CM6 (`ignoreEvent`); only `input` (while not composing), `compositionend` and `focusout` write back, and Zhuyin composition is handled entirely by the browser. The widget updates the same DOM through `updateDOM`, so a cell being typed in is never rebuilt; event handlers always re-read the table from the document with `posAtDOM` at that moment instead of keeping a possibly stale model. When the editor has focus and the cursor enters the table range (for example arrow keys moving in, or the menu's "Edit Markdown source"), the raw md is shown. Tables inside block quotes and lists stay raw md.
- **Math** (`math.ts`): extends the Lezer markdown grammar with `$…$` inline and `$$…$$` block (may be on one line); no bold, tag or card markup is parsed inside math. Inline rules follow Pandoc: the `$` after the opening and before the closing must not be whitespace, and the closing `$` must not be followed by a digit ("$5 and $10" is not math); a block whose closing `$$` has not been typed runs to the next blank line, and such unterminated blocks always show source and are not rendered (so right after typing `$$` and a newline the line does not turn into a blank formula); pressing Enter at the end of an opening line containing only `$$` adds the closing `$$` with the cursor in the middle (`mathKeymap`, `Prec.highest`, handled before markdown's list continuation). Rendering uses KaTeX (MIT): inline math is replaced by a widget by Live Preview on non-cursor lines, block math is a block widget (StateField) that shows source with a live preview below while the cursor is inside, and when the cursor is inside inline math (source) the rendered result floats below (a CM6 tooltip, reused while content and position are unchanged). KaTeX is not bundled into `editor.js`: `build.mjs` copies `katex.min.js`, the CSS and woff2 fonts to `Resources/Editor/katex/`, and the script is loaded with `<script>` the first time a document contains math (source is shown before it loads); the HTML of identical formulas is cached. Known limitation: the Swift-side card parser does not know about math, so `{{…}}` inside math is still treated as a cloze.
- **Property panel** (`frontmatter.ts`, `properties.ts`): top-level frontmatter fields show below the title (like Obsidian's Properties); values can be edited, fields renamed, types changed (text, list, checkbox, date), added and deleted; `icon` and `cover` are handled by the document header and are not shown. The type is inferred from the value: `true` / `false` is a checkbox, `YYYY-MM-DD` a date, `[a, b]` or `- a` lines is a list (`tags`, `aliases`, `cssclasses` are always lists), and nested structures and multi-line strings are display-only, with a click switching to raw YAML editing. Write-back replaces only that field's lines and keeps all other lines (including comments and unknown fields) byte for byte; a list keeps its original style (`[a, b]` or block, original indentation), and text that would be read as boolean, number or date is double-quoted. With no frontmatter, one is created from the header's "Add property", and deleting the last field removes the whole frontmatter; when frontmatter is added the cursor stays after it (not switched to raw YAML). Each change is an ordinary CM6 edit (undoable, written back after typing stops as usual); inputs are `<input>` elements inside widgets, never write back while composing, and Enter during composition goes to the input method. When the cursor enters the frontmatter the raw YAML shows and the panel is temporarily hidden.
- **Focus** (`editorFocus.ts`): tables, block math and inline-math previews show source only when the editor has focus (or the search bar is open) and the cursor is inside the range. Swapping `EditorState` (switching notes, or a rebuild on line-ending change) triggers no focus event, so after `setState` the focus state is always reset from `view.hasFocus`.
- **Find in note** (`search.ts`): ⌘F (the Mac menu item is turned into `exec("find")`; when focus is in the editor the CM6 keymap also handles it; keys inside a table cell do not pass through the CM6 keymap and are handled by the cell's keydown) opens a search bar above the editor; matching and highlighting use `@codemirror/search` (plain text, case-insensitive by default), while the bar itself is custom (localized, "n of m", showing "1000+" beyond 1,000). Enter / ⇧Enter and ⌘G / ⇧⌘G go to next / previous, Esc closes; only these bindings are kept, with no ⌘D or go-to-line. The search box is a plain `<input>` and Enter during composition goes to the input method. While the bar is open focus is in the search box, but a selected result inside a table or block math must be visible, so it also counts as "has focus" (`revealing`). Search state lives in `EditorState` and follows each note when switching.
- **Merge**: diff3 three-way merge. Non-overlapping edits merge automatically; only overlapping ones produce a conflict copy. When a remote change (sync or an external tool) arrives during editing, `applyRemote` applies it to CM6, preserving cursor and undo. The JS side remembers the content last equal to disk (`saved`) and the local edits not yet saved (`unsaved`, a `ChangeSet`); a remote change is transformed on top of the local edits with `ChangeSet.map` (`rebase.ts`), so characters typed within the last 300 ms of typing are never overwritten, and the merged content is then written back as usual.

## Bridge protocol (Swift ⇄ WebView)

| Direction | Message | When |
| --- | --- | --- |
| Swift → JS | `load({id, text, meta})` | Open or switch a note; `meta.modified` feeds the header |
| Swift → JS | `applyRemote({id, text})`, `setMeta` | Remote change pulled by sync; update the edit time after a write |
| Swift → JS | `exec({command, arg})` | Toolbar, shortcuts (`find` opens the search bar) |
| Swift → JS | `setLinkTargets(targets)` | Index changes (autocomplete, link cards) |
| JS → Swift | `ready` | Bundle loaded (pre-warming finished) |
| JS → Swift | `changed({id, text})` | 300 ms after typing stops, or on blur |
| JS → Swift | `openLink({target})`, `openTag({tag})` | Click on a `[[link]]`, `#tag` |
| JS → Swift | `pasteImage({data})` | Paste with an image and no text on the clipboard (base64; `pasteImage.ts` takes the paste over). Swift validates it with ImageIO (`ImageImport`: PNG / JPEG / GIF kept, other formats such as HEIC re-encoded as JPEG, ≤ 40 MB), saves it to `Attachments/` and inserts `![[…]]`; a one-off user action, never on the typing path |
| JS → Swift | `pickCover`, `pickIcon` | Header's change cover / icon (handled by native UI, written back to frontmatter) |

The theme does not go through the Bridge: `ThemeCSS.stylesheet()` is injected by WebEditorHost as a user script before the page loads, and light / dark follows `prefers-color-scheme`. The appearance preference (`AppTheme`: system / light / dark, `@AppStorage("appTheme")`, not written to the vault) is applied by the App layer with `preferredColorScheme` and also syncs `NSApp.appearance` / the window's `overrideUserInterfaceStyle`, so platform dynamic colors and the WebView's `prefers-color-scheme` follow it, without the Bridge. Images are inserted from the format bar's photo button (iOS: a menu with the photo library via `PhotosPicker`, which runs out of process and needs no photo-library permission, and the Files app; Mac: the file panel) or by pasting. Images are read through `vault://<vault-relative path>` (`WKURLSchemeHandler`), vault paths only; embedded previews such as `![[x.excalidraw]]` are served by `embed://<vault-relative path>` (see "Extension points" in [core.md](./core.md)). When a document icon is an SF Symbol (frontmatter `icon: sf:map`), Swift draws it as a PNG through `symbol:///<name>` and CSS colors it as a mask.

## Engineering for fluid editing

The core rule: **the typing hot path never crosses the Bridge**. Matching the feel of Obsidian and Typora relies on these seven points:

1. **The editor owns its state**: keystrokes are handled only inside JS; Swift receives changes only 300 ms after typing stops or on blur, and large files send a diff instead of the full text.
2. **One pre-warmed WebView**: the bundle loads at app launch; switching notes only swaps `EditorState` without reloading the page. Opened notes keep their state (the 20 most recent, LRU; `StateCache`), so switching back is instant with undo intact; beyond that the least recently used is dropped, and on a memory warning (iOS memory warning, macOS memory pressure) states not on screen are dropped. Dropping loses no content (saving happens before the switch); reopening rebuilds from disk content, losing only undo and cursor.
3. **Incremental parsing + viewport rendering**: Lezer parses incrementally and CodeMirror 6 renders only visible lines.
4. **Live Preview**: the cursor line shows md syntax and other lines are rendered to their final style with decorations.
5. **Native details**: `-apple-system` font, Dynamic Type, dark mode; the keyboard toolbar uses a native `inputAccessoryView`; macOS shortcuts go through the native menu and are forwarded; images are read locally by `WKURLSchemeHandler`.
6. **I/O never blocks the main thread**: atomic writes, `NSFileCoordinator` + file watching for external edits, index updated in the background.
7. **Open the last note at launch**: show cached content first, then load the editor.
