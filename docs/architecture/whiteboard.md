# Whiteboard (`.excalidraw`)

- **Does**: infinite canvas; ink layer (pen, eraser, lasso); structural layer with 6 element types: rectangle, ellipse, arrow (bindable to shapes), text, image, frame; select, move, resize.
- **Does not**: the Excalidraw web runtime; handwriting recognition and search indexing (ink is mostly brainstorming, not primary notes); live collaboration.
- **Implementation**: `PKCanvasView` handles ink and saves it as freedraw elements (the `ExcalidrawInk` conversion). Structural elements are drawn by UIKit / AppKit views (below) and serialized as standard Excalidraw elements. Unknown elements and fields are written back as is, so the file opens on excalidraw.com.
- **Platforms**: `PKCanvasView` exists only on iOS/iPadOS; on macOS ink is view-only and structural elements are editable.

**Design decisions**:

- **Stay native, no Excalidraw web runtime**: Excalidraw sends the whole scene on every stroke, so hosting it in a WebView would put Pencil input across the Bridge; Pencil latency, bundle size and an extra WebContent process are all not worth it either. When Excalidraw's advanced features are needed, use "open with another app" or excalidraw.com.
- **Structural layer uses layers, not SwiftUI Canvas**: one `CAShapeLayer` / `CATextLayer` per element (created only for elements on screen), with pan and zoom left to Core Animation; SwiftUI Canvas redraws everything every frame when zooming and cannot stay smooth with 1,000 elements. The structural layer sits under `PKCanvasView` and moves with its `contentOffset` / `zoomScale`; when zooming ends `contentsScale` is reset to keep lines sharp. Verified on an iPad Air M1; implementation rules:
  - The structural layer's transform is set synchronously in `scrollViewDidScroll` / `DidZoom` (screen coordinates = canvas coordinates × zoom − contentOffset) and committed in the same CATransaction as PencilKit, so it never lags a frame.
  - **Zoom bounce is off** (`bouncesZoom = false`): the bounce is a Core Animation animation during which the scroll view does not call back every frame, so the structural layer jumps to the end while the strokes are still animating and the two disagree.
  - **Raster scale follows zoom** (0.25…4): existing layers are not re-rasterized during zoom, new layers use the current scale; after zooming ends they are re-rasterized in batches. Creating and re-rasterizing layers is limited to about 120 per frame, with the rest left to later frames.
  - **Text layers turn off the `contents` action**: text is a bitmap `contents`, and by default a content change cross-fades for 0.25 s, so the old bitmap shown at the new scale leaves a growing / shrinking ghost. After changing `contentsScale`, call `displayIfNeeded()` within the same transaction. `CAShapeLayer` is vector and has no such problem.
  - 1,000 elements hold 60 FPS on 60 Hz devices; 10,000 elements drop to about 30 FPS (all on screen when zoomed out), which needs LOD (draw a bitmap snapshot at low zoom).
- **Stacking order**: in the editor ink is always above structural elements (`PKCanvasView` is a separate layer and cannot be inserted between shapes). On save the order of elements in the file is kept; thumbnails, embeds and the Mac view draw in file order.
- **Element scope**: all standard types can be **displayed** (rectangle, diamond, ellipse, line, arrow, text, freedraw, image, frame, including `angle` rotation, curved and elbow arrows); the ones that can be **created** are rectangle, ellipse, arrow (straight, bindable), text, image, frame. `embeddable`, `iframe` and similar show as a titled placeholder box and are preserved as is. rough.js's hand-drawn style is not simulated: `roughness`, `fillStyle` and `fontFamily` are preserved as is, display uses clean lines and system fonts, and new elements get `roughness: 0`.
- **Element order and fractional index**: newer Excalidraw elements have an `index` (fractional index). When present, elements are sorted by it and new elements get a valid index (inserted between two others); after merge, elements are sorted by `index`, and older files without `index` keep array order. The algorithm follows rocicorp/fractional-indexing (the same one Excalidraw uses, base62). A scene counts as "having indexes" only when every element has a valid index; older files are not backfilled (backfilling would bump `version` on every element) and new elements do not get one either. Equal indexes (two devices inserting at the same spot) sort by id, so both sides merge to the same result.
- **Arrow binding**: an arrow's `startBinding` / `endBinding` (`elementId`, `focus`, `gap`, plus `fixedPoint` in newer versions) and the shape's `boundElements` are maintained together. After a shape moves or resizes, the bound arrows' endpoints are recomputed, changing only the needed fields and incrementing `version`. Files exported from excalidraw.com serve as fixtures. Endpoint = the intersection of a ray from the adjacent point toward the anchor (the `fixedPoint` position on the shape, or the center if none) with "the shape's outline expanded outward by `gap`", so the endpoint's distance from the outline is `gap`; shapes can be rotated, and rectangle, ellipse and diamond each compute their own outline. `focus` is only an approximation for older Excalidraw and `fixedPoint` takes precedence. Elbow arrow endpoints are not recomputed yet (they would need re-routing). Deleting a shape clears that end's binding on the arrow; deleting an arrow removes it from the shape's `boundElements`; moving an arrow alone while the shape stays unbinds that end.
- **Text**: text with a `containerId` bound inside a shape moves with the shape and wraps centered inside it. Editing overlays a native `UITextView` / `NSTextView` on the element (Zhuyin composition is native) and writes back to the element only when editing ends.
- **Images**: standard format `files[fileId].dataURL` (embedded base64; the only form excalidraw.com can open). On insert, ImageIO scales to a longest side of 2048 px and converts to JPEG (images with transparency stay PNG) to avoid a JSON explosion; `fileId` is decided by the content hash so one image is embedded once; deleting an element does not delete `files` (the same as Excalidraw). Display generates thumbnails by size and never decodes the original.
- **frame**: children point to the frame with `frameId`; moving a frame moves its children, and frame content is clipped to the frame's bounds.
- **Every modification increments version**: any element change increments `version`, redraws `versionNonce` and updates `updated`; element-level merge (`ExcalidrawScene.merge`) relies on them.
- **Gesture split**: in pen mode, Pencil writes while a finger scrolls and zooms (iPad fixes `drawingPolicy = .pencilOnly` and ignores the system "Only Draw with Apple Pencil" setting; iPhone usually has no Pencil, so a finger can write too); a finger tap selects (empty space deselects), and only a long press of about 0.35 s drags a shape, avoiding accidental grabs while scrolling. Select mode disables PencilKit's gestures, and finger and Pencil both drag a shape they touch.
- **Undo**: structural operations register on `PKCanvasView`'s `undoManager`, sharing one stack with strokes in time order (⌘Z and the three-finger gesture both work).
- **An open whiteboard receives external changes**: Whiteboard registers an `EditorController`: `externalChange` merges disk content into the in-memory scene with `ExcalidrawScene.merge` and updates the view; `flush` saves immediately. Otherwise elements written by sync or Claude Code while the whiteboard is open would be overwritten by the stale scene.
- **Links**: when an element's `link` is a `[[note]]`, `index()` adds it to `links` (the whiteboard appears in backlinks); `renameLinks` updates `link` and `customData.easynotes.file`.
- **Shared renderer**: `SceneRenderer` (CoreGraphics, usable on a background thread) serves list thumbnails, `![[x.excalidraw]]` embeds and the Mac view; the editor's layer tree uses the same geometry (paths, text layout). Geometry is concentrated in `ElementGeometry` (outlines, lines and curves, arrowheads, rotation, view bounds); `SceneRenderer` and the layer tree both get their `CGPath` from it; `SceneRenderer.draw(in:visible:)` draws only elements intersecting the visible range, and the Mac view uses it directly.
- **Rendering values**: follow Excalidraw: corner radius (`roundness.type` 3 fixed 32, 25% for small shapes; 25% otherwise), arrowhead size and angle, dashed `[8, 8+w]`, dotted `[1.5, 6+w]`, a line whose end points are ≤ 8 apart can be filled. `fillStyle` is always drawn solid; frame outline and title use fixed styles (`#bbb` / `#999`) regardless of `strokeColor`; unknown types such as `magicframe` draw a placeholder box.
- **Ink width**: EasyNotes (PencilKit) strokes use the point sizes in `customData`; excalidraw.com strokes follow perfect-freehand (strokeWidth × 4.25, thinning 0.6). Semi-transparent elements are composited whole before opacity is applied.
- **Text and images**: text uses the already wrapped `text` in the file directly (Excalidraw wraps lines when saving) and is not re-laid out, so wrapping never differs from the web when font widths differ. Images decode at display pixels (power-of-two cache levels) and support `crop`, `scale` flips and rounded corners.
- **Thumbnail (`BoardPreview`)**: longest side 1600 px, scale ≤ 2; `lines` is the first 8 text elements; the PNG is stored separately as `<hash>.png` (PNG written before the JSON, regenerated if the PNG is deleted), memory keeps only the JSON, and the PNGs have a separate 32 MB cache cap. Known limitation: when dark mode inverts, images are inverted too.

**Canvas and editing core**:

- **The editing core is platform-independent**: tool state, selection, hit testing and the gesture state machines for drag / resize / create all work in canvas coordinates and call only the `ExcalidrawScene` editing API, so they can be unit-tested; iOS (`PKCanvasView`) and macOS (`NSView`) only convert touch / mouse events into canvas coordinates and hand them over. The layer tree (`CALayer`) is shared by both platforms.
- **Infinite canvas**: Excalidraw coordinates can be negative while `PKCanvasView` content coordinates start at 0, so `content coordinate = scene coordinate − origin`. On open, origin and `contentSize` are "content bounds expanded by a margin"; scrolling near an edge enlarges it, and when origin changes strokes are translated and `contentOffset` compensates so the view does not jump. On save strokes are converted back to scene coordinates, so the file always holds scene coordinates.
- **The canvas is always light**: structural element colors are written in the file (`#1e1e1e` etc.) while PencilKit automatically inverts stroke colors in dark mode, and the two would disagree, so the editor canvas is always light (`overrideUserInterfaceStyle = .light`, background from `viewBackgroundColor`). Dark mode (inverting the whole canvas like Excalidraw) comes later.
- **Undo**: each structural operation records dictionaries of the affected elements before and after the change and registers on `PKCanvasView`'s `undoManager` (sharing one stack with strokes). Undo writes back the earlier content but `version` keeps increasing (it never returns to the old number), otherwise other devices would think nothing changed and drop the undo in merge.

**Editing core details**:

- **`BoardEditor`** (`KindWhiteboard/Editor/`, `@Observable`): holds tool, selection and gesture state and modifies the `BoardDocument` scene directly. The event interface is canvas coordinates only: `tap` / `begin` / `drag` / `end` / `cancel` (plus Shift); the host converts coordinates and decides which touches to give it. During an operation the scene is modified every frame (`version` increments with it, the same as Excalidraw) and only at the end is one Undo registered and a save scheduled.
- **Saving**: `BoardDocument.edit` only changes memory and marks it dirty; the host does one `commit` 500 ms after interaction stops (or on leaving, or before an external change), sharing one timer with strokes.
- **Hit test**: topmost first; filled shapes, text and images can be hit anywhere inside, transparent shapes and frames only on their border (a frame also includes its title), and a selected element can be hit inside too; the tolerance is a fixed number of screen points (divided by the zoom). Text inside a shape selects the container; `groupIds` select all elements of the outermost group; `locked` elements and ink cannot be selected (iOS ink goes to the lasso, Mac ink is view-only).
- **Creating shapes**: rectangle, ellipse, frame and arrow are all created by dragging, and a drag too short creates nothing; after creation the tool switches back to select and selects the new element. An arrow's start and end bind when they land on a bindable shape (with a small tolerance outside the border); creating a frame gathers elements fully inside it.
- **Resizing**: a single element resizes in its own (unrotated) coordinate system with the opposite corner fixed; a multi-selection scales each element's rectangle proportionally to the overall bounds. Every frame is computed from the original elements at drag start, so errors do not accumulate. Flipping is not allowed (minimum 1). A single arrow shows two end handles, and dragging an end can rebind or unbind it.
- **Selection outline**: `SelectionOverlay` (CALayer, shared by both platforms) draws the selection box, handles, marquee and binding-target hints in screen coordinates above PencilKit, so handle size does not change with zoom.
- **Text editing**: the editor only records "which text is being edited" (existing text, text inside a shape, or the position of new text) and the scene at the start; the host overlays a native text box on the element accordingly (iOS `UITextView`, Mac `NSTextView`) with the same font size, line height, color, alignment and rotation as the element, following zoom, and hides that element's layer while editing. Typing changes only the text box and never touches the scene (Zhuyin composition is not interrupted); only when editing ends (click elsewhere on the canvas, switch tool, Esc, leave the whiteboard) is it written back once and one Undo registered. Ways in: text tool on empty space → new text (insertion point vertically centered at the click); text tool on text or a shape, or select tool double-click on text or a shape → edit that text / the text inside the shape (added if none, bound with `containerId`); select tool double-click on empty space → new text. If the content is blank at the end: new text is not created and existing text is deleted (when text inside a shape is deleted the shape stays). The tool then switches back to select and selects the text (text inside a shape selects the container). New text defaults to font size 20, `#1e1e1e`.
- **Insert image**: the toolbar's "Image" is a menu (Photos, File, Paste), not a persistent tool. Decoding and thumbnailing (`ExcalidrawScene.downscale`) run in the background and the insert happens back on the main thread; the image is centered in the view with a display size whose longest side is about 400 screen points (divided by the zoom). After insert the tool switches back to select and selects the image, one Undo (`files` is not removed by Undo, the same as delete). Photos use `PhotosPicker` (no photo-library permission needed).
- **iOS tools and gestures**: during structural operations `drawingGestureRecognizer` is disabled and the editor's drag gesture takes over (`canvas.panGestureRecognizer` waits for it to fail before scrolling): Pencil counts anywhere (marquee on empty space), while a finger drags only when it touches an element or handle and empty space keeps scrolling.

**Toolbar (Freeform style)**:

- **Top toolbar**: layout and ink tools follow "Ink toolbar" in [ui.md](./ui.md) (GoodNotes style, shared with PDF): Select | Pen, Highlighter, Eraser, Lasso | Sticky note, Shape, Note card, Text box, Image; with a selection, Style, Duplicate and Delete are added on the right; Undo / Redo sit in a floating capsule at the lower left. It is its own row below the navigation bar (file name, settings) and above the canvas (`safeAreaInset(edge: .top)`), the same on iPad and iPhone; it is not put in the navigation bar (which would crowd it with the file name). Mac shares the same view (without ink tools).
- **An ink tool = enter ink mode**: choosing pen, highlighter, eraser or lasso turns on ink mode and sets `PKCanvasView.tool` (`InkSettings`, no `PKToolPicker`); Pencil goes to PencilKit while a finger tap selects, a long press drags and a double tap edits text. Pressing "Select" leaves ink mode, disables PencilKit's gestures, and both Pencil and finger select. Ink mode is kept in `BoardEditor.inking` (platform-independent) and the current ink tool in `InkSettings` (an app preference). Holding the pen still makes a straight line (`StraightLineAssist`).
- **Insert instead of drag-to-create**: shapes (the popover shows icons only: rectangle, rounded rectangle, ellipse, diamond, arrow, Frame; names are for VoiceOver only), sticky notes and text boxes are all inserted at the center of the view, select the new element and register one Undo. When an element already sits at the same center position the new one is offset 20 to the lower right, so repeated presses do not stack. Default sizes: shapes 160×160 (screen points, divided by the zoom, likewise below), arrow length 200, Frame 400×300 (does not absorb existing elements). `BoardTool`'s drag-to-create stays in the editing core for Mac and keyboard shortcuts.
- **Selection style: rectangle / lasso**: pressing the "Select" button again while it is already selected toggles (the icon shows the current style), stored in an app preference (`@AppStorage("whiteboardSelectionShape")`). It affects only the marquee that Pencil drags on empty space outside ink mode; stroke selection in ink mode is the ink tool's "Lasso" (PencilKit's `PKLassoTool`). In the editing core the lasso is a `.lasso` gesture that records the points passed (at least 3 screen points apart) and selects elements "whose sampled points all fall inside the lasso polygon": shapes use the nodes of the outline path, lines and arrows their points, text and images their four corners, all with rotation applied; on release the polygon closes automatically. `SelectionOverlay` draws the lasso as a dashed line. Limitation: ink lives in `PKCanvasView` and structural elements in their own layer, so one selection cannot pick both to move together (that would require implementing stroke selection and moving ourselves, to be decided separately).
- **Choosing another tool leaves ink mode**: pressing Sticky note, Shape (once a shape is chosen), Text box, Image (once a source is chosen) or the Select button first turns ink mode off (back to select), with the editing core's insert API setting `inking = false` itself. Undo / Redo, Duplicate and Delete do not change the mode.
- **Sticky note**: a standard element combination that excalidraw.com can open: a borderless square-cornered rectangle (`backgroundColor: #ffec99`, `strokeColor: transparent`) 200×200, with the text inside (`containerId`) edited right after insertion. Insertion and text are one Undo each; the sticky note is kept even if nothing was typed (the same as Freeform).
- **Text box**: starts a new text at the center of the view (regardless of whether an element is at the center).
- **Canvas background**: the lower-right menu: None, Grid, Dots. It is an app preference (`@AppStorage("whiteboardBackground")`, default dots) shared by all whiteboards and not written to the file: Excalidraw has no field for a dotted background, and custom `appState` fields are dropped when excalidraw.com saves, which is also a compatibility risk. (Excalidraw's `appState.gridModeEnabled` was considered, but it offers only a grid and also turns on snapping, so the semantics differ.) Shown only in the editor; thumbnails and embeds do not draw it. Drawing: two `CAReplicatorLayer`s (dots or lines) under the structural layer following the same transform; spacing is 20 times a power of 2 so the on-screen spacing is at least about 14 points; dot size and line width are divided by the zoom each frame to stay constant on screen.

**macOS host, shortcuts, LOD**:

- **macOS host** (`BoardMacCanvasView`, `NSView`): Mac has no `PKCanvasView`, so no `NSScrollView` is used and pan and zoom are managed directly: `origin` (the scene coordinate at the top-left of the view) and `zoom` (0.25…4), screen coordinates = (scene coordinates − origin) × zoom; the structural layer, background and `SelectionOverlay` share the same layers and transform rules as iOS. Coordinates are scene-based to begin with, so `CanvasRegion` is not needed (an infinite canvas comes free). `BoardLayerTree(drawsFreedraw: true)`: ink is drawn by the structural layer (not selectable or editable, but it travels along when a frame is moved and is preserved as is on save). The canvas is always light (`appearance = .aqua`), the same as iOS.
- **Input**: two-finger scroll = pan; ⌘ / ⌥ + scroll or trackpad pinch = zoom around the cursor; mouse down / drag / up go straight to `BoardEditor` (`begin` / `drag` / `end`). A press without movement (< 3 points) counts as a click: it cancels the operation, restores the selection and calls `tap` instead (so Shift add / remove selection works); double-click = edit text. The text box is an `NSTextView` (Zhuyin composition is the system's) that scales content with `bounds` ≠ `frame`, so zooming while editing does not change the font or interrupt composition; `cancelOperation` ends editing (Esc during composition is handled by the input method). Undo uses the view's own `UndoManager` (the structural operations' stack; Mac has no strokes), available through the Edit menu and ⌘Z.
- **Toolbar**: reuses the iPad row (`BoardToolbar`, the same view on both platforms) with the ink tools hidden on Mac; when a creation tool is chosen by shortcut, the matching button is highlighted. It is not placed in the window toolbar to avoid crowding the breadcrumb and New Document.
- **Keyboard shortcuts** (platform-independent, `BoardShortcut`, shared by Mac and iPad with an external keyboard): V select, R rectangle, O ellipse, A arrow, T text, F frame (no modifier), Delete / ⌫ delete, ⌘D duplicate, ⌘A select all, ⌘C / ⌘X / ⌘V clipboard, Esc (end text editing → back to the select tool → deselect). Not intercepted while in a text box or ink mode (letters must go into the text box).
- **Autoscroll when dragging to the edge** (Mac): while dragging (move, resize, marquee / lasso, drag-to-create, arrow endpoint), when the cursor comes within 32 points of the view edge or leaves the view, the view scrolls that way, faster closer to the edge, at most 900 points/s (`EdgeAutoscroll`, platform-independent). After panning each frame, the same cursor position is converted to the new canvas coordinates and handed to `BoardEditor.drag`, so the marquee and moving elements extend along; it stops on release, on Esc cancel, or when the cursor returns to the middle. The display link runs only while scrolling. Not done on iPad (the other hand can scroll while a finger drags).
- **Cursor** (Mac): creation tools (rectangle, ellipse, arrow, frame) are a crosshair, the text tool an I-beam, select an arrow; managed with `resetCursorRects` and updated immediately when the tool changes (shortcut, toolbar, return to select after creating) by observing `editor.tool` with Observation.
- **Drag and drop images** (Mac): the canvas accepts image files from Finder, file promises (Photos and similar; received to a temporary folder first, then read) and image data dragged out of a browser (PNG / TIFF / JPEG / HEIC). The image is centered at the drop position, several images offset 20 points to the lower right in turn, one Undo each; decoding, thumbnailing and insertion go through the same `BoardEditor.insertImage(_:center:)` as the toolbar. Other files such as `.excalidraw` are not accepted (pasting Excalidraw elements still uses ⌘V).
- **LOD** (`BoardLOD`, shared by both platforms): when zoom ≤ 0.4 and more than 1,500 elements are in the visible range, `SceneRenderer` draws the visible range (plus a half-screen buffer) into one bitmap in the background and places it where the structural layer is, and the structural layer stops creating layers (existing ones are removed); until the snapshot is ready individual layers still show, so nothing goes blank. During zoom or pan the image follows the transform (temporarily blurry), and 150 ms after interaction stops it is redrawn for the new range and scale. When the zoom returns above the threshold LOD turns off and layers are rebuilt in batches. On iOS the snapshot excludes ink (`PKCanvasView` draws it itself).

**Style panel**:

- **Entry**: with a selection the toolbar gains a "Style" button (next to Duplicate and Delete) that pops up `StylePanel` (SwiftUI, the same view on iPad and Mac). The panel shows only the sections that apply to the selected elements, and in a multi-selection with inconsistent values it marks no option (a slider shows "Mixed").
- **All fields are standard Excalidraw fields** with no custom fields, so excalidraw.com can open and edit the file:
  - Fill `backgroundColor`: rectangle, diamond, ellipse.
  - Stroke `strokeColor` / `strokeWidth` (thin 1, medium 2, thick 4) / `strokeStyle` (solid, dashed, dotted): rectangle, diamond, ellipse, line, arrow. Stroke color has an extra "None" (`transparent`, which is what sticky notes use) for shapes only.
  - Corner `roundness`: rectangle (`{type: 3}`), diamond (`{type: 2}`); square corners = `null`.
  - Arrow `startArrowhead` / `endArrowhead`: none, arrow, triangle, bar, dot, diamond.
  - Text `strokeColor` (text color) / `fontSize` (small 16, medium 20, large 28, extra large 36, the same as Excalidraw) / `textAlign` (left, center, right): text, and text inside selected shapes. After a font size change the text is re-laid out: standalone text keeps its left edge / center / right edge by `textAlign` and its top edge fixed; text inside a shape lays out by its container, and the container grows when the text gets taller.
  - Opacity `opacity` (0–100, steps of 10): elements other than frames; a shape's opacity also applies to its text.
- **Preset palette only, no custom colors**: following Excalidraw's palette, stroke / text color use shade 4 (dark) and fill uses shade 1 (light). Stroke: `#1e1e1e`, `#868e96`, `#e03131`, `#c2255c`, `#9c36b5`, `#6741d9`, `#1971c2`, `#0c8599`, `#099268`, `#2f9e44`, `#f08c00` (shapes get an extra "None", which makes two rows of 6). Fill: none, `#e9ecef`, `#ffc9c9`, `#fcc2d7`, `#eebefa`, `#d0bfff`, `#a5d8ff`, `#99e9f2`, `#96f2d7`, `#b2f2bb`, `#ffec99`, `#ffd8a8`. Other colors in a file display as usual; the panel just marks nothing.
- **Editing API**: `ExcalidrawScene.setStyle(_ ids:, _ change: StyleChange)` (model layer, changes only applicable elements, increments version only when content changed, unit-testable); `BoardEditor.setStyle` registers one Undo per tap. The opacity slider modifies every frame while dragging and registers one Undo on release.
- **New elements reuse the last style** (Excalidraw's `currentItem*`): values changed in the panel are kept in `BoardEditor.currentStyle` (memory only; closing the whiteboard returns to defaults), and shapes, arrows and text inserted or drag-created afterwards get the applicable parts. Sticky notes, frames and images do not.

**Arrow connection-point snapping**:

- **Connection points**: bindable shapes (rectangle, diamond, ellipse, text, image) each have 4 connection points: the midpoints of the top, right, bottom and left edges (`fixedPoint` `[0.5, 0]`, `[1, 0.5]`, `[0.5, 1]`, `[0, 0.5]`, rotating with `angle`; for ellipse and diamond these are exactly the four vertices).
- **Snapping**: when drag-creating an arrow or dragging an arrow endpoint, an endpoint within 14 screen points (divided by the zoom) of a connection point snaps to it: the endpoint shows at the snapped position while dragging and on release binds and writes that `fixedPoint`. When not near a connection point but landing on a shape, the original behavior holds (`fixedPoint` = the proportion of the release position projected onto the shape). The range may slightly exceed the shape border (connection points are on the edge).
- **Endpoint position**: when `fixedPoint` is an edge midpoint, endpoint = that midpoint moved outward by `gap` along that edge's outward normal (no ray), so an arrow arriving from behind the shape still stops at the specified edge; other `fixedPoint`s keep using the intersection of the ray with "outline expanded by gap". After a shape moves, resizes or rotates it is recomputed by the same rule.
- **Hint**: `SelectionOverlay` draws the 4 connection points (white fill) on the binding target, with the one being snapped to solid and enlarged.
- **Not done**: routing of elbow and curved arrows; new arrows are still two-point straight lines.

## Note cards on the whiteboard (Heptabase / Obsidian Canvas style, optional)

Medium difficulty, on the premise that the whiteboard structural layer is complete.

- **Format**: one rectangle element represents a card (white, default 280×160 screen points) with `link` set to `[[note]]`, `customData.easynotes.file` recording the file path, and the title as text bound inside the rectangle. On rename, `renameLinks` updates all three (the title only if it still equals the old name; if the user changed it it is left alone). Any file type can become a card (links resolve by file name). On excalidraw.com it degrades gracefully into a box with a link.
- **Insert**: the toolbar's "Note card" pops up a file menu (`session.index.files()`, searchable, excluding the whiteboard itself), inserted at the center of the view, selected, one Undo.
- **Display**: the card's content is the file's `DocumentPreview` (title + first few lines, produced by that type's plugin preview; the whiteboard knows no file types and imports no other plugin): the whiteboard gets it through `DocumentSession.previewReader` (reusing the list thumbnail's hash cache) and stores it in `BoardDocument.cardPreviews`. A card with a preview has `NoteCardPainter` draw the title (18) and up to 6 body lines (14, one line per row, truncated with … when too long); the bound title text is hidden in the app (kept in the file for excalidraw.com). With no preview (type not registered, unreadable) the title text shows as usual. The preview is read-only, shown only in the app, and thumbnails and embeds do not draw it. It is re-fetched when content changes (`vaultChanged`), when the whiteboard opens, when a card is inserted, and after a sync merge.
- **Size follows content**: line height is fixed, so height = top and bottom padding + title + body lines × line height (minimum 64), with no need to measure text; width keeps the user's value. When the preview changes, `ExcalidrawScene.fitNoteCard` adjusts the card height and saves (the title text is re-centered and bound arrows recomputed). `customData.easynotes.fit` records the height of the last auto-fit: auto-adjustment happens only while the current height still equals `fit`, and once the user has resized by hand (height ≠ `fit`) it is never touched again. Auto-adjustment does not enter Undo.
- **Interaction**: double-clicking a card (`BoardEditor.editText(at:)` checks for a card first and does not enter text editing) calls the host's `openNote`, and the whiteboard hands it to `DocumentSession.openBeside`; on Mac / iPad the App opens that file's editor to the right of the main content as an `.inspector` (`VaultStore.sidePath`; the editor is supplied by the Registry by type, so it is not limited to notes), and the side file counts as "open" too (receives external changes, is not `close`d).
